1.Search Problems & Terminology

A search problem asks an agent to find a sequence of actions that gets it from where it is to where it wants to be. Solving one means exploring a state space — the set of all states reachable from the initial state by any sequence of actions — without necessarily building the whole thing in memory. The vocabulary below describes how a search algorithm keeps track of what it has explored and what it still has left to explore; it is the same vocabulary the interactive lecture's Search Terminology tab illustrates on a small eight-state graph, and the same vocabulary this page reuses throughout.

1.1The Search Tree

A search algorithm does not explore the state-space graph directly. Instead it builds a search tree over that graph: a tree of paths extending outward from the initial state, where each edge corresponds to one action. The distinction matters because search tree ≠ state-space graph — a single state can be reached by more than one path, so the same state can appear as more than one node in the search tree, one for each path that reaches it. The state-space graph has one node per state; the search tree can have many.

1.2States: Initial and Goal

A state s ∈ S represents one possible configuration of the world the agent cares about. Every search problem names one state as problem.INITIAL, the state the agent starts in, and provides a test IS-GOAL(problem, s) that recognizes whether a given state counts as a solution. Three questions are worth keeping separate while reading a search trace: where can the agent be (any state), where does it start (the initial state), and where does it want to end up (any state that passes IS-GOAL)?

1.3Expansion: Successors & Child Nodes

Expanding a node means applying every action available in its state and looking at where each one leads. EXPAND(node) does this by calling RESULT(s, a) = s′ for each legal action a, then wrapping each resulting state in its own CHILD-NODE(...). It is worth keeping the vocabulary precise: a successor is a state, produced by RESULT; a child is the search-tree node built around that state. Expanding a node with three legal actions produces three successor states and three child nodes, one per action.

1.4Reached, Expanded & Frontier

At any point during search, every state the algorithm knows about falls into one of three groups. A state is reached once some path to it has been found — it has a node, even if that node has done nothing yet. A node is expanded once its children have actually been generated. And a reached-but-not-yet-expanded node sits in the frontier: the set of nodes discovered but still waiting their turn. These three ideas are easy to blur together, so it is worth stating the one that trips people up most directly: reached does not mean expanded. A node can sit in reached and in frontier at the same time, waiting; only once it is popped and its children generated does it move into the expanded set. A typical mid-search snapshot might read reached = {A, B, C, E}, expanded = {A}, frontier = {B, C, E} — one node expanded, three more reached and waiting.

1.5Expansion Order

The expansion order is simply the sequence in which nodes are selected and expanded — n₁ → n₂ → n₃ → … — and it is the single most useful thing to track while reading a trace, since it is what actually distinguishes one search strategy from another. Two algorithms can explore the exact same state-space graph and disagree completely about expansion order: BFS empties the frontier roughly level by level; DFS drains one branch before ever coming back for a sibling; a priority-queue strategy expands in order of whatever quantity it is minimizing. The graph and the algorithm never change — only the order does.

1.6Redundant Paths

A redundant path is a second path to a state that has already been reached — formally, a child node whose node.STATE ∈ reached already. Redundant paths are common whenever the state-space graph has more than one route between two states (a city reachable from two different neighboring cities, say). Left unmanaged, they cause the same state to show up as more than one node in the search tree — wasted work at best, and at worst a search that never terminates if a redundant path can lead back to a state that leads back to it again.

1.7Tree-Like vs. Graph Search

Whether redundant paths get pruned is a design choice, not a law of nature — it is the difference between tree-like search, which keeps every path it finds as its own node (frontier only, no memory of what has already been reached), and graph search, which consults reached[state] = node before adding a child and discards the child outright if a path to that state already exists. Tree-like search is simpler but can re-explore the same state arbitrarily many times; graph search does more bookkeeping per node but guarantees each state is expanded at most once. Every strategy in Section 3 can be run either way — the pseudocode in Section 2.4 is written as graph search, since that is what the interactive lecture runs.

2.Search Data Structures

Every strategy in Section 3 is really the same algorithm with one piece swapped out: the ordering rule used by its frontier. This section covers the two data structures that make that swap possible — the search node, and the frontier itself — and then assembles them into the one generic search loop that BFS, DFS, UCS, Greedy, and A* all turn out to be instances of.

2.1The Search Node

A search-tree node is a small bundle of four fields, not just a bare state: node.STATE (which state it represents), node.PARENT (the node it was expanded from), node.ACTION (the action that produced it from its parent), and node.PATH-COST (written g(node), the total cost of the path from the initial state down to this node). A node for the state C reached from A via the action Go(C), at a running cost of 2, would read STATE = C, PARENT = A, ACTION = Go(C), PATH-COST = g(C) = 2. The parent pointers are what let a solved search recover the actual sequence of actions at the end — the algorithm just walks node.PARENT back up to the root.

2.2Frontier Operations

Whatever data structure implements it, every frontier supports the same four operations: IS-EMPTY(frontier) tests whether any nodes remain; TOP(frontier) looks at whichever node would come out next, without removing it; POP(frontier) removes and returns that node; and ADD(node, frontier) inserts a newly generated node. IS-EMPTY and TOP only ever peek — the frontier's contents never change because of them. Only POP and ADD change what is actually waiting.

2.3Frontier Types

The frontier's ordering rule — which node TOP/POP hand back next — is the one thing that turns this generic algorithm into a specific strategy:

  • A FIFO queue (first-in, first-out) always returns the node that has been waiting longest. This is breadth-first behavior.
  • A LIFO stack (last-in, first-out) always returns whichever node was added most recently. This is depth-first behavior.
  • A priority queue always returns whichever node scores lowest under some evaluation function — g(node) for uniform-cost search, h(node) for greedy search, g(node) + h(node) for A*.

Run all three over the same graph from the same starting frontier and they diverge immediately: the FIFO queue's search tree grows level by level and tends to need the most expansions to find any particular goal; the LIFO stack's tree dives straight down whatever branch it discovered most recently, reaching a goal in very few expansions in the best case while never even looking at whole other branches; the priority queue's tree always grows toward whichever node is currently cheapest by its own measure.

2.4Best-First Search, in General

With a node structure and a swappable frontier, the entire search loop collapses to eleven lines. Starting from a node for the initial state, with the frontier and reached table both genuinely empty, the algorithm repeats one cycle until either the frontier runs dry (failure) or a popped node passes the goal test (success): pop the next node, test it, and if it is not the goal, expand it and push every child that is either newly reached or reached more cheaply than before.

Best-First-Search (graph-search form)
function BEST-FIRST-SEARCH(problem) returns a solution node or failure
    node ← NODE(problem.INITIAL)
    frontier ← a queue containing node
    reached ← {problem.INITIAL: node}
    while not IS-EMPTY(frontier) do
        node ← POP(frontier)
        if IS-GOAL(problem, node.STATE) then return node
        for each child in EXPAND(node) do
            if child.STATE not in reached or
                    child.PATH-COST < reached[child.STATE].PATH-COST then
                reached[child.STATE] ← child; ADD(child, frontier)
    return failure

Every strategy in Section 3 is BEST-FIRST-SEARCH with one line changed: the ordering rule inside frontier. Breadth-first search and uniform-cost search are exactly this algorithm with a FIFO queue and a g(node)-ordered priority queue, respectively; depth-first search is the same loop with a LIFO stack; greedy search and A* swap in priority queues ordered by h(node) and g(node) + h(node). Nothing else about the loop changes — which is exactly why the interactive lecture's Putting It Together stepper can walk the same eleven lines for both BFS and UCS and only ever point at line 3 (frontier ← a queue) to explain why their traces diverge.

3.Search Strategies

The strategies below are grouped, in the traditional way, by how much they know about the goal's location. Uninformed strategies (BFS, DFS, UCS, IDS, plain Bidirectional Search) only know the problem definition itself — the state space, the actions, and the goal test — and nothing about how close any given state is to a solution. Informed strategies (Greedy Best-First Search, A*, SMA*) additionally use a heuristic function h(n), an estimate of the cost remaining from state n to the nearest goal, to guide the search toward the goal rather than outward in every direction at once.

3.1Uninformed vs. Informed Search

Every node a search algorithm holds can be scored by two quantities: g(n), the cost already paid to reach it, and h(n), the estimated cost still remaining. An uninformed strategy's frontier can only ever be ordered using g(n) or plain insertion order, since h(n) is not available to it; an informed strategy can combine the two, most commonly as f(n) = g(n) + h(n), an estimate of the total cost of the cheapest solution that passes through n. The practical effect shows up immediately on the same frontier viewed both ways: a node that looks unremarkable by g(n) alone can rank at the top once h(n) is folded in, because the heuristic recognizes it as sitting close to the goal even though little has been spent to reach it yet.

Uninformed: no h(n) · Informed: uses h(n) · f(n) = g(n) + h(n)

3.2Breadth-First Search

Breadth-first search expands the shallowest unexpanded node first, which a FIFO frontier gives for free: nodes come out in exactly the order they went in, so the search finishes an entire depth level before starting the next one. BFS is also usually implemented with an early goal test — checking a child the instant it is generated, rather than waiting for it to be popped — since doing so returns a solution at the shallowest possible depth without any extra expansions. That shortcut has a cost, though: the first goal BFS generates is guaranteed to be shallowest, not necessarily cheapest, so on a graph with unequal step costs BFS can return a shallow, expensive path while a deeper, cheaper one still exists.

3.3Depth-First Search

Depth-first search expands the deepest unexpanded node first. A LIFO stack produces this behavior automatically: whatever was added most recently comes out next, so the search commits to one branch and follows it as far as it goes before ever backtracking to try a sibling. DFS uses the standard goal test — a node is checked only once it is popped and selected, not the moment it is generated — and its successors are conventionally pushed in reverse order, so that the stack still pops them out in the same left-to-right order the other strategies use.

3.4Uniform-Cost Search

Uniform-cost search replaces the FIFO queue with a priority queue ordered by g(n), the path cost accumulated so far, and always expands the cheapest node on the frontier. Because a later-discovered path to a state can turn out to be cheaper than an earlier one, UCS uses the standard goal test and continues to update reached whenever a cheaper path to a state is found, superseding the earlier, more expensive one. This is what guarantees optimality: UCS never returns a goal node until it is certain nothing cheaper remains on the frontier.

3.5Iterative Deepening Search

Iterative deepening search runs depth-limited depth-first search — DFS that refuses to expand any node past a fixed depth limit — over and over, starting the limit at 0 and increasing it by one each time the previous attempt fails to find a goal. Every iteration restarts from scratch and re-explores the shallow levels it already searched, which sounds wasteful, but because the number of nodes at each depth grows exponentially, the repeated shallow work is dwarfed by the cost of the final, deepest iteration — IDS ends up asymptotically no worse than BFS in the nodes it generates, while needing only DFS's linear memory.

3.6Bidirectional Search

Bidirectional search runs two searches at once — a forward search from the initial state, following successors, and a backward search from the goal, following predecessors — and stops once some state has been reached by both. The appeal is asymptotic: if both searches expand outward from their respective ends at similar rates, they meet somewhere near the middle of the path, after roughly the square root of the nodes a single one-directional search of the same depth would have needed. A concrete, cost-ordered version of this idea is described below as BiBF: both directions run as priority queues ordered by g(n), and at each step the search expands whichever direction's frontier currently holds the cheaper node, continuing past the first meeting point only until no remaining combination of a forward and a backward node could beat the best meeting cost already found. Run this way, bidirectional search inherits uniform-cost search's guarantees in each direction: complete when step costs are bounded below by ε > 0, and optimal, since it never stops early on a meeting point that a cheaper combination could still beat.

3.7Greedy Best-First Search

Greedy best-first search orders its priority queue by h(n) alone, always expanding whichever node the heuristic estimates is closest to the goal — completely ignoring g(n), what it has already cost to get there. That single-mindedness makes it fast when the heuristic is good, but it is easy to mislead: a node that looks close to the goal by the heuristic's estimate can sit at the end of an expensive path, and greedy search has no mechanism to notice. It will happily commit to that path anyway.

3.8A* Search

A* orders its priority queue by f(n) = g(n) + h(n), combining what greedy search and uniform-cost search each do alone: g(n) keeps it honest about cost already paid, and h(n) keeps it aimed at the goal instead of expanding outward in every direction. Provided the heuristic never overestimates the true remaining cost — it is admissible — A* run as tree-like search is guaranteed optimal; the slightly stronger condition of consistency (h(n) ≤ cost(n, a, n′) + h(n′) for every edge) is what extends that guarantee to graph search. In practice A* with a good heuristic explores dramatically fewer nodes than uniform-cost search while still finding the same optimal solution.

3.9SMA*: Memory-Bounded A*

SMA* (Simplified Memory-Bounded A*) is A* with a hard cap on how many nodes it may hold at once. When that cap is reached and a new node needs room, SMA* forgets its worst leaf — the one with the highest f-value, and therefore the least promising — and backs up that leaf's f-value to its parent. Recording the discarded value at the parent matters: it stops the parent from ever being mistaken for as cheap as it first looked, so if every other option turns out worse, SMA* can still regenerate the forgotten branch and pick up where it left off.

Evaluation Function
f(n) = g(n) + h(n), plus a fixed memory bound

Priority queue ordered by f(n), capped at a fixed number of nodes; the worst leaf is forgotten (and its value backed up to its parent) whenever the cap is reached
Complete?
Yes, if a solution exists whose nodes fit within the memory bound
Optimal?
Yes, under the same memory condition as completeness
Time Complexity
Can exceed A*'s — a forgotten subtree that turns out to be needed again must be regenerated
Space Complexity
Bounded by construction — never exceeds the fixed memory limit

3.10Goal Testing: Standard vs. Early

The generic algorithm in Section 2.4 tests IS-GOAL right after popping a node — the standard goal test. Some strategies instead test each child the moment EXPAND generates it, before it is even added to the frontier — the early goal test — trading a small amount of bookkeeping for the chance to stop one generation sooner. The early test is only safe when the first-generated goal is guaranteed to be the one the algorithm actually wants: true for BFS, since every step costs the same and the first-generated goal is therefore guaranteed shallowest. It is not safe for UCS or A*, where a goal generated early is not necessarily the cheapest one — using the early test there could return a correct-looking but suboptimal solution, exactly the failure mode the standard test is built to avoid.

Standard: IS-GOAL(node.STATE), tested on POP · Early: IS-GOAL(child.STATE), tested on EXPAND

4.Evaluating Search Algorithms

With eight strategies on the table, the natural next question is how to compare them. Four criteria, applied consistently, do the job: whether a strategy is guaranteed to find a solution at all (completeness), whether it is guaranteed to find the cheapest one (optimality), and how much time and memory it may need along the way. All four are usually expressed in terms of five quantities that describe the shape and cost structure of the search tree itself.

4.1b, d, m, C*, ε

Two of these quantities describe depth, and two describe cost — worth keeping straight, since they measure different things and do not have to move together. The branching factor b is how many children a node typically has. The depth of the shallowest solution d and the maximum depth m of the state space are both depth quantities. The optimal solution cost C* and the minimum positive step cost ε > 0 are both cost quantities — and, as the figure below shows, the shallowest solution and the cheapest one are not required to be the same node.

b = branching factor · d = depth of shallowest solution · m = maximum depth · C* = optimal solution cost · ε > 0 = minimum positive step cost

4.2Time Complexity

A search algorithm's time complexity is normally expressed as however many nodes it may need to generate — not wall-clock time, since that depends on the hardware, but node count, which does not. BFS and IDS, which explore level by level (IDS by repetition), generate on the order of every node down to the shallowest solution: O(bd). DFS and greedy search, in the worst case, can be forced down a branch all the way to the tree's maximum depth before finding anything: O(bm). UCS's bound is stated in terms of cost rather than depth, since that is what it actually searches by: O(b1+⌊C*/ε⌋), the branching factor raised to roughly how many ε-sized steps fit inside the optimal cost. A*'s worst case is exponential as well, often written O(bd), but an informative heuristic can shrink the number of nodes actually generated well below that bound.

4.3Space Complexity

Space complexity counts how many nodes an algorithm may need to hold in memory at once, and this is where the uninformed strategies split sharply into two camps. BFS, UCS, and A* all keep every node they generate — the entire frontier, plus everything in reached — so their space bounds match their time bounds exactly. DFS and IDS need only the current path from the root down to wherever they are now, plus each level's unexplored siblings along the way, which is why their space bounds — O(bm) and O(bd) respectively — are so much smaller than their time bounds. This is the whole reason iterative deepening exists: it accepts BFS's repeated shallow work in exchange for DFS's memory footprint.

4.4Completeness

An algorithm is complete if it is guaranteed to find a solution whenever one exists — which also means correctly reporting failure whenever one does not, rather than searching forever. Completeness turns out to hinge on a small number of structural guarantees: a finite branching factor rules out an algorithm getting stuck expanding one node's infinitely many children; a positive lower bound ε on step cost rules out an infinite sequence of ever-cheaper paths that a cost-ordered strategy could chase forever without ever reaching the cheapest one. BFS, IDS, UCS, and A* each satisfy the conditions relevant to them and are complete. DFS and greedy search are not complete in general — both can be led down an infinite (or merely very long) branch with nothing to pull them back, unless the state space is finite and graph search prunes repeated states.

4.5Optimality

An algorithm is optimal if, whenever it returns a solution, that solution's cost equals the true optimal cost: C(solution) = C*. Finding a solution is not the same as finding the best one, and BFS is the clearest illustration of the gap: because it uses an early goal test and stops at the shallowest goal it generates, it can return a shallow, expensive path while ignoring a deeper, cheaper one still sitting unexplored on the frontier — exactly the situation the interactive lecture's BFS trace walks through, where the shallow route (cost 10) is found before the truly cheapest one (cost 8) would have been. UCS and A* avoid this by using the standard goal test and refusing to return a goal until nothing better remains possible on the frontier, which is precisely what makes them optimal.

4.6Comparing the Strategies

Put together, the eight strategies trade completeness, optimality, time, and space against each other in different combinations — no single strategy dominates every column, which is exactly why the choice of strategy matters.

Exercise 1

Tracing Four Search Algorithms on a Tree

Successors are considered in alphabetical order. For DFS and IDS, successors are pushed onto the stack in reverse alphabetical order, so that they still come off the stack in alphabetical order. Using the tree below (goal state O), find the expansion order, solution path, and path cost for each of:

(a) Breadth-First Search · (b) Depth-First Search · (c) Iterative Deepening Search · (d) Uniform-Cost Search

(a) Breadth-First Search

BFS expands level by level and uses the early goal test, so a child is checked the instant it is generated rather than waiting for its turn to be popped. It clears depth 1 (A, B), then depth 2 (C, D, E, F), then depth 3 (G, H, I, J) before expanding I at depth 3 turns up O as its first (alphabetically) successor — the search stops there, so O is never formally selected off the queue.

Expansion order: START, A, B, C, D, E, F, G, H, I
Solution path: START → B → E → I → O · Path cost: 1+1+1+1 = 4
(b) Depth-First Search

Because successors are pushed in reverse alphabetical order, the stack still pops A before B — so DFS commits to START's entire A-subtree (all thirteen nodes under it: C, D, G, H, M, N, Q, R, S, T, U, V) before ever backtracking to try B. Every one of those thirteen nodes is irrelevant to the goal, but DFS has no way to know that. Only once that whole branch is exhausted does it pop back to START and descend into B, where E and then I are each the alphabetically-first (and only newly-tried) child, so O — I's first child — is reached immediately, with no detour through P.

Expansion order: START, A, C, G, M, Q, S, U, V, T, R, N, H, D, B, E, I
Solution path: START → B → E → I → O · Path cost: 4
DFS finds the same path as BFS here only because O happens to be the alphabetically-first descendant at every level of the B branch — a coincidence of this tree's labeling, not a property DFS can be relied on for in general.
(c) Iterative Deepening Search

IDS reruns depth-limited DFS with the limit starting at 0 and increasing by one each time the previous attempt fails. O sits at depth 4 (START→B→E→I→O), so every limit below 4 fails outright — including limit 3, where I is reached and selected but sits exactly at the limit, so it is never expanded and O is never generated. Limit 4 repeats the same depth-limited traversal one level deeper and this time reaches, expands, and selects O.

Exercise 3

Why Early Goal Test Works for BFS but Not UCS

An early goal test checks a node the instant it is generated as a successor, rather than waiting until it is selected (popped from the frontier). Explain why this shortcut is safe for Breadth-First Search, but not for Uniform-Cost Search.

Show Answer
BFS: generation order already equals cost order

BFS expands nodes in strict order of non-decreasing depth, and every edge carries the same implicit unit cost, so path cost is a monotone function of depth alone — a goal one level shallower is always strictly cheaper. BFS's FIFO frontier guarantees no shallower node is ever left unexpanded while a deeper one is processed, so the very first time a goal is generated, no cheaper (shallower) goal could possibly still be waiting undiscovered. "First generated" and "cheapest" are the same moment, so testing at generation time is free of risk — and it saves the wasted work of queuing and later re-expanding the goal.

UCS: generation order and cost order can disagree

UCS's frontier is ordered by cumulative cost g(n), but nodes are not necessarily generated in that order. In Section 3.2's worked example, expanding D generates the goal G with g(G)=8 — but E is still sitting in the frontier at that moment with g(E)=7 < 8. Stopping the instant G was generated would report cost 8 as final, without ever checking whether continuing through E reveals something cheaper. The only way to certify a node's cost is minimal is to wait until it is popped as the frontier's current minimum — at that point, since all edge costs are non-negative, nothing left in the frontier (or still undiscovered) can produce a cheaper route to it. That is exactly the late-goal-test argument reused in Exercises 5 and 7.

Early goal test is safe only when frontier order = cost order.
Exercise 4

Proving Time and Space Complexity by Induction

Prove the time and space complexity of BFS, DFS, IDS, UCS, A*, and Greedy Best-First Search using mathematical induction.

Show Answer

Each proof below inducts on a notion of "layer" — depth for the uninformed algorithms, cost-band for the informed ones — and shows that layer k+1's node count is bounded in terms of layer k's, the way every one of these bounds is actually derived.

(a) BFS — O(bd) time and space

Claim: after BFS has processed every node through depth k, it has generated at most 1+b+b2+…+bk nodes.

Base case (k=0): only the root has been generated — 1 = b0. Inductive step: assume depth k holds at most bk nodes. Each generates at most b children, so depth k+1 holds at most b·bk = bk+1 nodes, and the cumulative total becomes (1+b+…+bk)+bk+1 = 1+b+…+bk+1 — exactly the claim at k+1.

Conclusion: through depth d, total nodes generated = ∑i=0d bi = O(bd). Since BFS keeps every generated node in the frontier or reached until the search ends, space shares the same bound.

(b) DFS — O(bm) time, O(bm) space

Time: the identical induction from (a), carried out to the tree's maximum depth m instead of stopping at d (DFS has no preference for shallow goals), gives total nodes generated ≤ ∑i=0m bi = O(bm).

Space claim: when the deepest node expanded so far sits at depth k, the frontier holds at most b·k nodes. Base case (k=0): the frontier holds at most b nodes (the root's own children). Inductive step: a stack discards a subtree's frontier entries once that subtree is fully explored, so descending to depth k+1 adds at most one new sibling group (≤ b nodes) on top of the ≤ b·k already held from shallower levels, giving ≤ b·(k+1).

Conclusion: at depth m, the frontier never exceeds b·m = O(bm).

(c) IDS — O(bd) time, O(bd) space

Time: IDS is d+1 depth-limited DFS runs, one per limit ℓ=0,…,d, and by (a)/(b)'s induction restricted to depth ℓ, run ℓ costs O(bℓ). The total is ∑ℓ=0d bℓ. By induction on d (base case d=0: sum =1=(b1-1)/(b-1); step: (bk+1-1)/(b-1) + bk+1 = (bk+2-1)/(b-1)), this geometric sum equals (bd+1-1)/(b-1) = O(bd) — the same order as one BFS run, since the final iteration's cost dominates all the shallow work repeated before it.

Space: IDS never holds more than one iteration's stack at a time, so it inherits DFS's O(bm) bound from (b) applied at the final, deepest limit reached (m=d when a solution exists) — O(bd).

(d) UCS — O(b1+⌊C*/ε⌋) time and space

Define cost layer j as the nodes with optimal cost g*(n) ∈ [jε, (j+1)ε). Claim: layer j holds at most bj nodes. Base case (j=0): only the start node has g=0 — 1=b0. Inductive step: since ε is the minimum step cost, every child of a layer-j node has cost at least (j+1)ε, so it lands in layer j+1 or later, never back in layer j. Each of the ≤ bj layer-j nodes has ≤ b children, so layer j+1 receives at most bj+1 of them.

Conclusion: UCS only ever expands nodes with g(n) ≤ C* before reaching an optimal goal (it always takes the frontier's cheapest item first), so the nodes involved are bounded by layers 0 through ⌊C*/ε⌋: ∑j=0⌊C*/ε⌋ bj = O(b1+⌊C*/ε⌋), by the same geometric-sum identity as (c). Time and space share this bound, since UCS keeps every generated node until it is expanded.

(e) A* — same worst-case bound as UCS

By the lemma proved in Exercise 5 (an admissible h means A* only selects nodes with f(n) ≤ C* before an optimal goal), define layers by f(n) instead of g(n): layer j = {n : f(n) ∈ [jε, (j+1)ε)}. Because f = g+h increases by at least ε per edge (g does, and h ≥ 0), the identical induction from (d) applies verbatim, giving layer j ≤ bj nodes.

Conclusion: A* touches only layers 0 through ⌊C*/ε⌋ before terminating, so its worst-case time and space share UCS's O(b1+⌊C*/ε⌋) bound — unsurprising, since h≡0 makes A* identical to UCS. A well-informed heuristic shrinks how many nodes actually reach a low f-layer in practice, but it cannot change this worst-case order.

(f) Greedy — O(bm) time and space

Time: a poor heuristic gives no useful guidance, so in the worst case greedy can be led down every branch to the maximum depth m before stumbling onto the goal — the identical induction from (b)'s time argument gives ∑i=0m bi = O(bm) nodes generated.

Space: unlike DFS, greedy's frontier is a priority queue, not a stack — a sibling is never discarded once a different branch is chosen; every generated node stays in the frontier until it happens to be popped. So the same induction that bounded generated-node count in the time argument also bounds frontier size, since nothing is ever freed except by expansion (which only adds more nodes): at depth m this gives O(bm) space too — DFS's linear-space trick does not carry over to a priority-queue frontier.

Exercise 5

A* Is Cost-Optimal

Using proof by contradiction, prove that A* is cost-optimal.

Show Answer

Setup: let h be admissible (h(n) ≤ h*(n), the true cheapest cost from n to a goal, for every node), and let C* be the true optimal solution cost, achieved by goal G1. Assume, for contradiction, that A* (tree-like search, standard goal test) instead terminates by selecting a suboptimal goal G2, with g(G2) > C*.

Step 1. Because the optimal path to G1 is finite, at the moment A* selects G2 some node n on that optimal path must still be sitting in the frontier — either G1 itself, or an ancestor of it whose subtree has not yet been fully explored.

Step 2. Since h is admissible, h(n) ≤ h*(n), so f(n) = g(n) + h(n) ≤ g(n) + h*(n) = C* — the cost of reaching G1 via n is exactly C*, by definition of the optimal path.

Step 3. A* always selects the frontier node with minimum f. Since it selected G2 instead of n: f(G2) ≤ f(n) ≤ C*. But h(G2)=0 at any goal, so f(G2) = g(G2). This gives g(G2) ≤ C*.

Contradiction: Step 3's g(G2) ≤ C* directly contradicts the assumption g(G2) > C*. So the assumption was false — A* cannot terminate on a suboptimal goal. A* is cost-optimal.

This tree-search argument needs only admissibility. Graph search (with a shared reached set) needs the stronger consistency condition, because admissibility alone doesn't stop a later, cheaper path to an already-reached node from being wrongly discarded.
Exercise 6

IDS and Equal Step Costs

Prove that IDS is optimal only if all cost steps are equal.

Show Answer

Worth separating two different claims before proving anything: completeness (does IDS find some solution?) and optimality (is the solution it finds the cheapest one?) are not the same guarantee, and the question asked is specifically about the second one. As Section 4.4's summary table already shows, IDS is complete whenever the branching factor b is finite — regardless of step costs. What genuinely requires equal step costs is optimality. The proof below establishes both halves precisely.

Completeness holds unconditionally (for finite b)

If a solution exists at some finite depth d, IDS's outer loop tries every integer limit 0,1,2,… in turn. Since b is finite, each depth-limited DFS run explores a finite tree and terminates (Exercise 4b). So the limit =d iteration is guaranteed to be reached eventually, and at that limit the depth-d solution is reachable and will be found. This argument never used the size of any step cost — only that b is finite and d is finite. So completeness does not depend on step costs at all.

Optimality requires equal step costs

IDS returns whatever solution the first successful iteration finds — the shallowest one. Shallowest is only guaranteed cheapest when path cost is a non-decreasing function of depth, which holds unconditionally when every step has the same cost c (then cost = c × depth, so shallower is strictly cheaper). Proof by counterexample when costs are unequal: let node P be a goal at depth 1 reached by one step of cost 100, and node Q be a different goal at depth 2 reached by two steps of cost 1 each (total cost 2). IDS's limit-1 iteration finds P first and returns it immediately — cost 100 — despite Q, cost 2, being the true optimum. So without equal (or at least depth-monotonic) step costs, IDS is not optimal, even though it remains complete.

Exercise 7

UCS Is Complete and Optimal

Prove that UCS is complete and optimal.

Show Answer
Completeness

Assume step costs are ≥ ε > 0 and a goal exists at finite cost C*. UCS always expands the frontier's minimum-g node, so the minimum cost remaining on the frontier is non-decreasing over time, and it strictly increases by at least ε every time the previous minimum is expanded (Exercise 4d's layer argument: with b finite and step costs bounded below by ε, only finitely many nodes have g(n) ≤ C*). Since UCS never skips over a cheaper node in favor of a more expensive one, and only finitely many nodes are cheaper than or equal to C*, UCS must reach the goal after expanding a finite number of nodes. UCS is complete.

Optimality

Suppose UCS selects a goal G with g(G) = g1. Because UCS always expands the frontier's cheapest node first, by the time G is selected, every node with cost strictly less than g1 has already been expanded and had its cheapest cost recorded in reached — so no undiscovered path cheaper than g1 can still exist to any node, G included. If a cheaper path to G existed, it would have produced a frontier item with cost < g1, which UCS would have expanded first, selecting G at that lower cost instead. This contradicts G being selected at cost g1, so no such cheaper path exists: g1 = C*. UCS is optimal.

Exercise 8

DFS Is Not Cost-Optimal

Prove that Depth-First Search is not cost-optimal.

Show Answer

Disproving a universal claim — "DFS always returns the minimum-cost solution" — only takes one counterexample where it fails.

EdgeCost
S → A10
A → G1 (goal)0
S → B1
B → G2 (goal)1

S's successors, alphabetically, are A then B. DFS pushes them so A is explored first: pop S, expand, push B then A; pop A, expand → generates G1; pop G1 — goal test succeeds — DFS stops and returns S → A → G1 at cost 10. It never visits B, G2, or the path of cost 1+1=2 at all.

DFS returns: S → A → G1 · Cost 10
True optimum: S → B → G2 · Cost 2

Since 10 > 2, DFS returned a solution that is not the cheapest one reachable. Its stack discipline and late goal test only ever ask "is this the goal?" — never "is this the cheapest goal?" — so it has no mechanism to prefer a low-cost branch over whichever one it happens to explore first. DFS is not cost-optimal.

This is exactly why UCS exists: ordering the frontier by g(n) instead of stack order is what turns "first found" into "cheapest found" whenever step costs are unequal (Exercise 7).
