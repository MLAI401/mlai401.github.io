We begin with a physical grid representation of the environment. The maze contains traversable corridor cells, black wall obstacles, a starting location S, and a goal location G.

In a physical grid, search algorithms must explore cell-by-cell. For large grids, this creates a massive search space. Can we abstract this environment?

3. First Abstraction — 4T State Space

A navigation decision is only needed at turning points, corners, dead-ends, the start (S), or the goal (G). Intermediate grid cells along straight corridors are abstracted away.

State = (Turning Point, Orientation)
Turning Points (T): 25
Orientations: 4
State Space Size: 100
State space is reduced from 4K (280) to 4T (100) states. We have removed intermediate grid points, but we still retain orientation because it affects steering.

We connect turning points by tracing the corridors. Each abstract action represents a direct path between nodes, with the cell distance as the transition cost.

• Cost: Cell distance along each corridor (edge weight).

1. 8-Puzzle Setup

The standard 8-puzzle contains 8 numbered tiles and 1 empty position (blank space '_') on a 3 × 3 grid. The target is to rearrange the tiles from their initial arrangement to the goal arrangement.

Grid Size: 3 × 3
Tiles: 1 - 8
Blank Position: 1
A state in the 8-puzzle is a single, complete configuration of tiles and the blank. Moving a tile changes the puzzle state.

2. State Representation

To store the board state in computer memory, we represent it as a simple, immutable 9-element list or tuple: (7, 2, 4, 5, 0, 6, 8, 3, 1), where 0 denotes the blank position.

state = (7, 2, 4, 5, 0, 6, 8, 3, 1)
Any two boards with tiles in different positions represent different states. For example, (7,2,4,5,0,6,8,3,1) ≠ (7,2,4,5,3,6,8,0,1). Complete board arrangements define unique states.

3. Actions & Transition Model

The transition model defines which actions are possible in a state, and the resulting state after applying an action: RESULT(s, a) = s'. In this puzzle, we define actions from the perspective of moving the blank space.

Move Blank Action Model:
Blank

4. Possible Configurations Size

How many total arrangements of the 8 tiles and blank are mathematically possible? Since there are 9 slots, there are 9 factorial total arrangements:

9! = 362,880 possible arrangements
But are all of these 362,880 arrangements actually reachable from our initial configuration? Let's analyze reachability next.

5. Parity & Solvability Presets

The 362,880 arrangements form two completely disconnected components (parity classes) of size 181,440. You can only move within your group; legal moves cannot cross the parity divide.

6. Exploration & Duplicates

Try moving tiles to explore the state space. Notice that moving blank in a loop (e.g. Left, Right, Left) returns to a state you have already visited. A search tree tracks duplicate states to avoid looping infinitely.

8. Concept Summary

A quick-reference guide of core AI Search concepts taught by the 8-puzzle demo:

Question Concept / Answer
What is a state? One unique board arrangement of tiles & blank
What is a state space? Set of all theoretically possible configurations (9! = 362,880)
What are actions? Moves of blank space (Up, Down, Left, Right)
What is the transition model? RESULT(s, a) yielding a new state s'
Are all states reachable? No, parity constraints divide permutations into 2 disconnected groups

Step 1: Environment & PEAS Formulation

Two-Room Vacuum Robot Environment (AIMA)

The environment consists of two rooms (Room A and Room B). Each room is either Clean or Dirty, and the robot is located in one of the two rooms.

Environment State
$$\text{State} = (\text{Robot Location}, \text{Room A Status}, \text{Room B Status})$$

Current: (A, Dirty, Dirty)

Robot Percept
$$\text{Percept} = (\text{Current Location}, \text{Current Room Status})$$

Observed: (A, Dirty)

Performance Measure
$$\text{Score} = 10 \times (\text{Cleaned}) - 1.5 \times (\text{Moves})$$

+10 per dirty room cleaned, -1.5 per Left/Right move, 0 for Suck/NoOp.

Manual Environment Controls (Demonstrate Transitions)

Step 2: Table-Driven Agent

Table-Driven Agent: Action = TABLE[Percept History]

The Table-Driven Agent stores the entire history of observed percepts and looks up the corresponding pre-calculated action in a lookup table. It does not reason about the world; it strictly pattern-matches the accumulated percept sequence.

Accumulated Percept History Grows by 1 percept per step
History empty []
Table Lookup Match Formula: Entire History → Table Lookup → Action
Step the agent to inspect the lookup key and action match.
Key Teaching Limitation: As the sequence of percepts grows, the number of possible histories grows exponentially ($4^T$ for $T$ steps). A table-driven agent quickly exhausts memory in realistic environments.
Step 3: Simple Reflex Agent

Simple Reflex Agent: Current Percept → Condition-Action Rule → Action

The Simple Reflex Agent selects actions based strictly on the current percept. It stores zero memory and has no internal model of the other room.

Memory Footprint
Memory: NONE (0 Bytes)

Cannot remember previous percepts or the status of unobserved rooms.

Condition-Action Rules
IF Current Room is Dirty THEN Suck
ELSE IF Location == A THEN Right
ELSE IF Location == B THEN Left
Crucial Teaching Distinction: Completes Cleaning $\neq$ Knows It Is Complete!
Both rooms are clean ($\text{Room A}=\text{Clean} \land \text{Room B}=\text{Clean}$). However, when the robot is at Room B, its percept is only (B, Clean). Because it has no memory of Room A, it executes Left. At Room A, it executes Right, falling into an infinite oscillation loop.
Step 4: Model-Based Reflex Agent

Model-Based Reflex Agent: Percept + Internal State Model → Updated Model → Rule → Action

The Model-Based Reflex Agent maintains an internal state model tracking the cleanliness of both Room A and Room B. It updates its internal model upon observing percepts and predicting the effect of its own cleaning actions.

Agent Internal State Model State: (A Status, B Status)
Room A Knowledge
Unknown
Room B Knowledge
Unknown
Model-Based Decision Rule Stops with NoOp when both rooms known Clean
Step agent to observe internal state updates and decision rules.
Memory Efficiency: The agent does not need the entire percept history. It only maintains the minimal internal model ($2 \text{ variables}$) required to reflect the unobserved world and stop cleanly with NoOp.
